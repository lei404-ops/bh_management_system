# BHMS – Boarding House Management System

A Laravel 13 web app for running a boarding house: rooms, tenants and leases, monthly billing (rent + utilities), payments with verification, and maintenance tickets. It has four user roles: **admin, landlord, tenant, staff**.

> This README covers (1) how to run and open the system and (2) how to sign in as each user and what each one can do.

---

## 1. Tech stack at a glance

| Item | Details |
|---|---|
| Framework | Laravel 13 (PHP ^8.3) |
| Database | **MySQL** (`bh_management_system`) – required, see note below |
| Front end | Blade views + plain JS/CSS in `public/assets` (no npm build needed) |
| Auth | Session login (database sessions, 120 min idle timeout), role middleware `role` |
| Local server | XAMPP (Apache + MySQL) + `php artisan serve` |

> **MySQL is required.** The queries use MySQL-only features (`FIELD()`, `NOW()`, `INTERVAL`, a database view `v_monthly_revenue`). The `database/database.sqlite` file in the project is empty and is **not** used.

## 2. How to access the system

### Prerequisites
- Windows with **XAMPP** (Apache + MySQL) and **PHP 8.3+**
- **Composer** (the zip already includes `vendor/`, so you normally don't need to run `composer install`)
- A terminal opened in the project folder (VS Code terminal is fine)

### Steps

1. **Start XAMPP** – click *Start* for **Apache** and **MySQL**.
2. **Create the database** – open <http://localhost/phpmyadmin> → *New* → name it `bh_management_system` → collation `utf8mb4_unicode_ci` → *Create*.
3. **Check `.env`** (already configured for XAMPP defaults):
   ```
   APP_URL=http://localhost:8000
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=bh_management_system
   DB_USERNAME=root
   DB_PASSWORD=
   ```
   If `.env` is missing, copy `.env.example` to `.env` and run `php artisan key:generate`.
4. **Build the tables and load the sample data** (from the project folder):
   ```bash
   php artisan config:clear
   php artisan migrate:fresh --seed
   ```
   ⚠️ `migrate:fresh` **drops every table** first. Use it only for first-time setup or to reset to demo data.
5. **Run the app:**
   ```bash
   php artisan serve
   ```
6. **Open** <http://localhost:8000>. You are redirected to `/login`. After login, every role lands on `/dashboard`, which shows a role-specific view.

### Optional: monthly billing job
Invoices are generated by a command (idempotent – safe to run repeatedly):
```bash
php artisan bhms:monthly-billing            # current month
php artisan bhms:monthly-billing 2026-11    # a specific month
```
It (1) creates the month's invoices (rent + utilities) once per lease, (2) marks past-due invoices overdue, and (3) sends lease-expiry alerts and expires finished leases. It is also scheduled daily at 01:00; for that to run automatically, use `php artisan schedule:work` (dev) or Windows Task Scheduler / cron calling `php artisan schedule:run` every minute.

## 4. How to access each user type

### 4.1 Admin  (`admin@bhms.test`)  and  4.2 Landlord  (`landlord@bhms.test`)

Admin and landlord have **identical permissions** in the current code (they are always checked together as "managers").

**Menu:** Dashboard · Rooms · Tenants · Maintenance · Change password

| Page / URL | What they can do |
|---|---|
| **Dashboard** `/dashboard` | Key metrics (revenue, occupancy, overdue bills, pending tickets), 6-month revenue chart, leases ending within 30 days, **payments awaiting verification**, recent tickets, notifications |
| **Rooms** `/rooms` | Search/filter rooms, **add a room**, **change room status** (available / occupied / maintenance), see who occupies each room |
| **Tenants** `/tenants` | Search tenants, **add a tenant** (creates the login + profile, optionally assigns a room and creates the lease), **enable/disable** a tenant login, **reset a tenant's password** (a temporary password is shown once) |
| **Maintenance** `/maintenance` | See **all** tickets, **assign** a ticket to staff, change ticket status, view ticket photo and timeline |
| **Payments** (dashboard panel) | **Confirm or reject** tenant payments; record a payment directly as confirmed (e.g., cash received in person) |
| **Receipts** `/receipt?id=…` | View/print any payment receipt |
| **Change password** `/account` | Change own password |

### 4.3 Tenant  (`tenant1@bhms.test`, `tenant2@bhms.test`)

**Menu:** My Dashboard · Browse Rooms · My Requests · Change password

| Page / URL | What they can do |
|---|---|
| **My Dashboard** `/dashboard` | Lease summary, outstanding balance, **monthly statements** (invoices), payment history, notifications |
| **Pay an invoice** | Click pay on an invoice → choose method (cash, bank transfer, GCash, Maya, demo gateway), enter amount (cannot exceed the balance) and a reference number or upload a receipt image (JPG/PNG/WebP, max 2 MB). The payment stays **pending** until an admin/landlord confirms it |
| **Browse Rooms** `/rooms` | View rooms and rates (occupant names are hidden) |
| **My Requests** `/maintenance` | **Submit** a maintenance request (category, priority, description, optional photo) for their current room; track status; **cancel** their own *pending* requests |
| **Receipts** `/receipt?id=…` | Only receipts for their own payments |
| **Change password** `/account` | Change own password |

Cannot open: `/tenants` (returns **403**).
A tenant needs an **active lease** to submit maintenance requests.

### 4.4 Staff  (`staff@bhms.test`)

**Menu:** Dashboard · My Tickets · Change password

| Page / URL | What they can do |
|---|---|
| **Dashboard** `/dashboard` | Workload counts for tickets assigned to them, notifications |
| **My Tickets** `/maintenance` | See **only tickets assigned to them**; move a ticket to **in progress** or **resolved** with a note |
| **Change password** `/account` | Change own password |

Staff cannot assign tickets and cannot see payment receipts.

## 5. Adding new users

- **Tenants:** log in as admin/landlord → **Tenants → + Add tenant**. Leave the password blank to auto-generate one; it is shown **once** in a "Tenant login" box – copy it and give it to the tenant.
- **Admin / landlord / staff:** there is **no screen** for creating these. Add them in phpMyAdmin (table `users`, set `role`, and a bcrypt `password_hash`) or with `php artisan tinker`:
  ```php
  DB::table('users')->insert([
    'full_name' => 'New Staff', 'email' => 'newstaff@bhms.test',
    'password_hash' => Hash::make('ChangeMe123'), 'role' => 'staff',
  ]);
  ```
- **Forgot password:** tenants → ask an admin/landlord to reset it. Other roles → reset via tinker, e.g. `DB::table('users')->where('email','staff@bhms.test')->update(['password_hash'=>Hash::make('NewPass123')]);`
- **Locked out?** Wait 15 minutes, or clear the table: `DB::table('login_attempts')->truncate();`

## 7. Troubleshooting

| Problem | Fix |
|---|---|
| `SQLSTATE … Unknown database` | Create `bh_management_system` in phpMyAdmin (step 2) |
| `Access denied for user 'root'` / connection refused | Start MySQL in XAMPP; check `DB_*` in `.env`; run `php artisan config:clear` |
| `No application encryption key` | `php artisan key:generate` |
| Blank/ugly page, no CSS | Open via `http://localhost:8000` (not by double-clicking files); CSS lives in `public/assets` |
| "Too many failed attempts" | Wait 15 min or truncate `login_attempts` |
| Changes to `.env` ignored | `php artisan config:clear` |
| Port 8000 busy | `php artisan serve --port=8080` and update `APP_URL` |
| Can't see a page (403) | Your role isn't allowed – e.g., tenants/staff cannot open `/tenants` |

## 8. ⚠️ Security notes found while analyzing the code

These matter before the system is used outside a classroom/demo setting:

1. **Tenant management API is not restricted to admin/landlord.** The comments say "admin + landlord only – enforced by route middleware," but `routes/web.php` registers `/api/tenants` under the general `role` group (any logged-in role), and `TenantController` has no role check. In practice a logged-in **tenant or staff** user who calls the API directly could list tenants, create tenant accounts, disable a tenant, or **reset another tenant's password**. The UI hides this, but the API doesn't block it.
   **Fix:** in `routes/web.php`, change the two tenant lines to
   `Route::get('/tenants', …)->middleware('role:admin,landlord');` and `Route::post('/tenants', …)->middleware('role:admin,landlord');` (or add a role check at the top of `TenantController`).
2. **Payments API is open to staff.** The comment says admin/landlord/tenant only, but staff can call `/api/payments`: they can list **all** invoices and payment history, and `submit` has no staff check.
   **Fix:** use `->middleware('role:admin,landlord,tenant')` on the payments routes.
3. **Rooms page/API is reachable by staff** (just hidden from the menu). Low risk, since it is read-only for non-managers.
4. **Admin and landlord are the same role in practice.** If you want the landlord to be more limited (or admin to have extra rights such as user management), the permission lists need to be split.
5. **`APP_DEBUG=true`** in `.env` shows detailed errors. Set it to `false` for any real deployment.
6. Sample passwords are all `Password@123` – change them (or remove the sample users) before real use.
